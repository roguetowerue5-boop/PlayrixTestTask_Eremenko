# Сборщик офферов

Собирает финальную картинку оффера (подложка + 10 карточек товара) из
материалов `C:\Playrix\Cutted`, строго следуя алгоритму из
`C:\Playrix\RuleForBuilding\rule_building.txt`, и сверяется с референсом
`RuleForBuilding\blue_template.png`.

Отдельный standalone-скрипт, ничего общего с проектом `OfferForge` не имеет
(там свой похожий, но отдельный движок сборки).

## Запуск

Самый простой способ — двойной клик по **`run_and_check.bat`**. Он сам:
1. проверяет, что установлен Python;
2. проверяет/ставит зависимости (`pillow`, `pyyaml`);
3. проверяет, что папки `Cutted`, `RuleForBuilding`, `Icons` на месте;
4. запускает сборку (`example_config.yaml` -> `result.png` по умолчанию);
5. проверяет, что результат реально создался и не пустой;
6. открывает готовую картинку.

Если что-то не так — печатает `[FAIL]` с причиной и ждёт нажатия клавиши,
не закрывая окно.

Свой конфиг и/или имя выходного файла — первым и вторым аргументом:

```
run_and_check.bat my_collection.yaml my_result.png
```

Ручной запуск без батника:

```
python build_offer.py --config example_config.yaml --out result.png
```

Параметры:

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--config` | (обязателен) | YAML-конфиг коллекции |
| `--out` | `result.png` | Куда сохранить результат |
| `--cutted-dir` | `C:\Playrix\Cutted` | Папка с материалами |
| `--reference` | `C:\Playrix\RuleForBuilding\blue_template.png` | Референс для сверки |
| `--icons-dir` | `C:\Playrix\Icons` | Заглушки картинок товара |
| `-v` | — | Подробный лог |

Зависимости: `Pillow`, `PyYAML` (`pip install pillow pyyaml`).

## Конфиг коллекции

См. `example_config.yaml`. Кратко:

```yaml
title: "Farming"          # заголовок в ленте подложки
items:                     # ровно 10 штук, по 5 в ряд, сверху вниз слева направо
  - name: "Star Map"
    rarity: 1               # число звёзд, 1-5
    image: null              # имя файла из Icons или полный путь; пусто -> заглушка
    badge: null               # текст на бейдже, напр. "+2"; пусто -> бейджа нет
```

## Размер результата

Сборка всегда идёт в родном масштабе `BackGround.png` (3630×2414 — в этом
масштабе заданы все локальные координаты и сетка), а на выходе картинка
приводится к фиксированному финальному размеру **3587×2426** (`OUTPUT_SIZE`
в `build_offer.py`). Это единое масштабирование на ~1-2%, не искажение —
пропорции 3587×2426 почти точно совпадают с пропорциями содержимого
референса.

## Как это соответствует rule_building.txt

Шаги скрипта (`build_offer.build_offer`) один в один повторяют разделы
правила:

1. **Референс** — `load_reference` открывает `blue_template.png`.
2. **Материалы** — `load_materials` читает всё из `Cutted/`.
3. **Проверка наличия** — там же: если файла нет, сборка останавливается
   с понятной ошибкой.
4. **Разметка** — `detect_card_area` находит на подложке границу между
   лентой заголовка и синим полем карточек (по цвету, не захардкожено —
   сработает и на слегка другой подложке того же стиля), `compute_grid`
   раскладывает 10 рамок 5×2 отступами от центра этой области.
5. **Подстановка** — `compose_card` кладёт на каждую рамку неймплейт,
   картинку (или заглушку из `Icons`, если не задана), звёзды, бейдж,
   текст названия и цифру на бейдже — в этом порядке, как в разделе
   "Логика сборки" правила.
6. **Проверка позиций** — `verify_background_matches_reference` и
   `verify_grid_fits` логируют расхождения с референсом/выход сетки за
   границы поля; при отклонении печатается предупреждение, а не тихий сбой.

### Локальные координаты рамки

Как и требует правило ("используются локальные координаты бордера, где
0.0 — это центр бордера"), позиции неймплейта, окна под картинку, звёзд и
бейджа внутри карточки заданы в системе координат, где `(0, 0)` — центр
`Border.png` (см. `BorderSpace` и константы `*_LOCAL` в начале файла).
Числа вымерены дважды и сведены воедино:

- по прозрачности самого `Border.png` (где окно под арт, где проходит
  плашка-разделитель под неймплейт);
- по пиксельному анализу `blue_template.png` (где на референсе реально
  стоят звёзды и бейдж относительно рамки карточки).

Обе системы совпали в одном масштабе 1:1, поэтому одни и те же числа
работают для обоих источников.

## Что осталось за скобками

- **Прогресс-бар** (`Progressbar.png`) в `rule_building.txt` не описан —
  он подключается только если в конфиге `show_progressbar: true`, и
  используется как есть, со своим примером-значением ("8/25" зашито в
  сам файл). Поле `set_progress` в конфиге зарезервировано на будущее.
- **Бейдж**: `Badge.png` в Cutted уже содержит зашитый текст "+2". Скрипт
  закрашивает эту область цветом самого бейджа и печатает поверх заданный
  в конфиге текст — работает для любого текста, а не только "+2".
- Правило упоминает звёзды "от 1 до 4", но в `Cutted` есть готовый пресет
  и на 5 — скрипт поддерживает `rarity: 1..5`.
